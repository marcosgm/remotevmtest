Cost and time to complete

Estimated USD per job, not an invoice. VM runtime includes staging and final upload; the additional processing duration is modeled, not measured.

What matters

Moving compute away from storage adds a one-time transfer cost and staging delay. A lower GPU hourly price can offset that premium when enough processing reuses the local data. Repeated remote reads or large frequent checkpoints can change the outcome.

Measured baseline and assumptions

The timing baseline is the median of 3 complete jobs per location on matching CPU VM sizes (host CPUs can differ). Each job downloaded all five packed archives, checked their hashes, processed 421,587 logical files on local temporary SSD, fitted a small filename-size model three times, and uploaded one small result. It made five input GETs and one result PUT; processing made zero Blob calls.

Staging includes local disk writes, fsync and SHA-256 checks with 4 parallel downloads. TTFB includes connection setup and is the median across all input GETs. Whole-job time is a separately measured median; it is not the sum of individual stage medians. Repeated local work may use the OS page cache. These timings do not predict another GPU VM's network, disk or training performance.

Workload projections: changing file count or size is a what-if estimate, not a new experiment. The transfer model separates the baseline stage into a payload component and ceil(files / 4) request waves at the measured median TTFB. It scales only the payload component by the size ratio, then adds the new request waves, so baseline TTFB is not counted twice. Baseline processing scales linearly with bytes; additional processing hours do not. The original whole-job timing residual and small final result remain fixed. File size distribution, tiny-object overhead, service limits, local SSD capacity and GPU throughput can invalidate these extrapolations.

Cost includes the entered VM prices and egress, Cold input retrieval and transactions, shared input storage and ingestion, small result storage, private endpoint hours and payload processing, plus time-allocated OS disk and public IP. Ingress is free; egress is counted once at the source, not at both ends. Storage uses binary GiB; transfer estimates use decimal GB.

Defaults allocate shared input costs across 30 jobs/month over 90 days. Cold capacity has a 90-day minimum retention charge, including early deletion; each result also incurs that minimum. Initial upload writes are conservatively priced at Cold rates. Dedicated endpoint hours round up per job; retained endpoint hours are allocated across monthly jobs. Disk allocation uses a 730-hour month.

At the original workload the ingestion ledger is used exactly. Other workloads assume equally sized input files and estimate one block-list commit per file plus 16-MiB block uploads. Payload storage, retrieval and transfer scale with total bytes; input GET transaction costs scale with file count. Result size stays fixed.

Shared service rates are held fixed while you vary the three pricing inputs. Private Link processing is based on application payload rather than an invoice meter. Provisioning, idle VM time, unmeasured OS-disk operations, diagnostic traffic, taxes and contract-specific adjustments are excluded. Staging and checkpoint behavior, data residency and actual GPU speed must be validated for the target workload.
